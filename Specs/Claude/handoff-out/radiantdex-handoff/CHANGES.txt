NEW

Specs/Claude/jbd-pages-handoff/radiantdex-data.jsx
  Ported reference data for this design sandbox — verbatim field names/values from
  app/src/data/{books,orders,characters,ideals}.js (ES modules there -> window globals
  here, per PROJECT-STRUCTURE.md's two-worlds split). Not app code; a preview-only mirror.
  → app terms: no new app file — the real data already lives in app/src/data/.

Specs/Claude/jbd-pages-handoff/radiantdex.jsx
  The three RadiantDex screens in one router: index (Orders-as-spine grid, with your own
  Order featured as a full hero card; character grid; reading-progress control), Order
  detail (hero + meta + readonly Ideals-ladder echo + roster), Character detail (hero with
  portrait slot + meta chips, exemplifies/summary lede, Coppermind link, "Also walking this
  path" roster cross-links). Includes the spoiler-gate treatment: gated entries obscure via
  the existing Women's Script engine (womens-script/womens-script.js) with an inline
  reading-progress control to reveal — DESIGNED per spec §3.2, not enforced.
  → app terms: app/src/pages/RadiantDex.jsx, routes /radiantdex, /radiantdex/order/:orderId,
  /radiantdex/:slug. Split into per-route components when porting (RadiantDexIndex,
  OrderDetail, CharacterDetail are already separate functions in this file).

Specs/Claude/jbd-pages-handoff/radiantdex.css
  Additive page-component layer for the above — same token/accent discipline as
  jbd-styles.css (reuses --accent/--stormlight, .glass/.pill/.card-launch, and the
  existing .books/.gemstone + .ladder-pop vocabulary rather than inventing parallel
  patterns). Order-card and char-card also pick up the same card-link hover treatment
  (accent border + glow + lift) that oath-card already had — that hover was previously
  scoped only to .oath-card.card-link.
